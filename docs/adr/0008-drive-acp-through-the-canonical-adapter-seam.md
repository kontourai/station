# Drive ACP through the canonical adapter seam

Station connects ACP agent apps through a single `acp` provider adapter that satisfies `ProviderAdapterShape` and emits Canonical runtime events, multiplexing the user-configured ACP connections as adapter implementation. The chat-route ACP branch and its chat-SSE mapping layer are retired in one cutover rather than strangled, because the orchestration chat path is already proven for the other External-agent adapters and a lingering bridge would preserve the second event vocabulary the change exists to eliminate. App-neutral vocabulary (plan updates) is promoted into the canonical contract with a typed plan surface in the workspace; app-specific notifications (such as the `_kiro.dev/*` family) ride one namespaced extension event, because the canonical contract is Station's single event vocabulary and must not absorb any one app's implementation details. Existing chat-route ACP conversation history is not migrated to orchestration sessions; stored conversation files are left on disk but are not surfaced on the new path.
