Settings you may not have found

Most Settings rows explain themselves. This page covers four sections that change what Station offers rather than how it looks. Open Settings, pick a page in the left rail, or search for a setting by name. You can also find any Settings row from the command palette (⌘K or Ctrl+K).

Feature previews

Feature previews are features that are still being evaluated. Each one has a switch, a name and a description of what turning it on does. A preview is listed only when this Station's build can run it; if none is, the section says "No previews are currently offered". Previews start off.

Task review (task-review): turn this on in Settings → Advanced → Feature previews, then open a Task and choose Review, after Conversation. Choose its plan, Brief, output or answer, select text and comment. Expand a thread for its history; use Send or Send + Resolve to ask the live lead agent to act, or Copy for agent to copy the discussion. Outdated means the quoted text can no longer be relocated; a changed revision alone is separate.

Choose Capture beside Screens, then select a Browser session from the Task's Project and capture it. Commit workspace changes first. Place a region pin with the pointer, or focus the image target, use the arrow keys and press Enter, then comment. Captures retain the commit and appear through the Task's authorized image route. Turning the preview off hides Review; a taskView=review link then opens Overview.

Chat images from the host (chat-host-images): when a reply finishes, Station copies the PNG, JPEG, GIF and WebP images it names by absolute path or file: URL, from the chat's working folder, a verified worktree of it, or the chat's own temporary folder, and shows them in the reply on every device. See visual replies for what is admitted and what each "not available" message means. Turning it off stops new copies; copies already made stay with their chat.

Turning a preview on affects everyone who uses this Station.

For Local speech, choose Station (local) in Settings → Voice → Speech-to-text after enabling the preview. Click the composer microphone to record and click again to stop; final text appears after transcription. Missing tools require the Station operator’s explicit station media-tools download --yes consent against this instance; there is no download settings panel yet. Disabling the preview removes the provider when the UI observes the change and cancels pending client dictation. See local speech for requirements, limits and error recovery.

Developer tools

Enable developer tools shows the Developer page in Customize and the command palette, and its Monitoring page in the command palette. It is off by default; a direct /developer link still opens when it is off.

Enabling it also reveals five independent previews: Flow delivery preview, Veritas readiness preview, Trust preview, Sheet gestures preview, and Station routes preview. Each starts off and is saved on this device. The tools require both Developer tools and their own preview switch to be on. Turning Developer tools off makes them unavailable without clearing those saved choices. These device previews are separate from the Station-wide Feature previews above.

Sheet gestures preview adds a drag handle to the top edge of sheets that open from the bottom of a phone-width screen. Drag it up to expand the sheet to nearly full height, drag it down to close the sheet, or tap it to switch between the two heights. Closing this way is the same as choosing the sheet's close button. Confirmation prompts and sheets that cannot be dismissed get no handle, and the handle can only be dragged with touch or a pointer; the close button and Escape still close every sheet.

Station routes preview adds Routes to the Devices page: every address this device reaches the current Station on, which one is in use, which failed and why, and Add route for an address you type. Edit removes routes you added. While connected, the app also learns the LAN, Tailscale and Tailscale HTTPS addresses the Station reports, marked "found automatically". The app saved on a phone or desktop lists those addresses but still connects only through its saved one; see Station routes.

Device hosts

A device host is another Mac or Linux computer that runs iOS simulators or Android emulators for Station over SSH. Station uses your SSH agent and configuration and never stores a key. Only the Station operator sees this section, and only on a personal Station.

  1. Confirm the host key once in a terminal: ssh user@host.
  2. Choose Add device host and enter a Name and an SSH target, such as me@build-host.example or an alias from your SSH config.
  3. Choose Test connection. Station checks that it can reach the host and that Node.js, Xcode simulators and the Android SDK are available.
  4. Choose Enable device hub and confirm Install and enable. Station installs its device hub on the host under ~/.station-device-host.

Each host's menu also offers Share devices…, Disable hub, Edit and Remove. A Station can have up to 32 hosts. The mobile device workspace guide explains what you can do with the devices once a host is ready.

Nearby Stations

On the computer running Station, Settings → Pairing → Discover this Station nearby makes its name and local address visible to nearby devices. It starts off and only the computer's local operator can change it. The status below the switch says whether publication succeeded; enabling it does not change your network or firewall. Connecting still needs your approval. See Connect your phone.

About

Settings → About shows the app version, links to Build details and Diagnostics, the open source packages bundled into the app with their licenses, and links to the privacy policy, license and support. Development servers have no license list.

Link to a setting

Every Settings row has a stable address of the form /settings?view=<section>&highlight=<row>, for example /settings?view=feature-previews&highlight=feature-previews. See Settings deep links.
