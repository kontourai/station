# Design Records

Files in this directory preserve design decisions and their evolution. They
are developer records, not end-user documentation, and their continued
presence does not mean every proposal or vocabulary choice is current.

Use these authorities in order:

1. [The glossary](../glossary.md) for current vocabulary.
2. [The module map](../architecture/module-map.md) for current ownership and
   implementation seams.
3. Source and tests for shipped behavior.
4. A design record for the reasoning and constraints it explicitly owns.

A design record should identify whether it is a proposal, accepted direction,
implemented contract, superseded record, or historical snapshot. When a file
names a successor, read the successor rather than treating the older body as
current guidance. Historical terminology remains in superseded records when
rewriting it would falsify the decision that was made.

For agent identity and vocabulary specifically,
[agent-engine-unification.md](agent-engine-unification.md) supersedes the
type-based portions of [entity-hierarchy.md](entity-hierarchy.md). Current
product copy uses Station agent, External agent, Provider, Model, Task, and
Session as defined by the glossary; ACP is a connection method, not an agent
category.
